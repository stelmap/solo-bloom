
- Client acquisition metrics (CAC, revenue/cost) are computed client-side in src/lib/clientSources.ts from clients/expenses/income; revenue excludes prepayment withdrawals to avoid double counting.

- Appointment queries use stable scheduled_at/id ordering and pagination through fetchAllPages so API row limits cannot hide later meetings.
- Treat appointment timestamps as UTC-labelled practice wall clocks; use calendarClock for practice-timezone comparisons and date navigation without shifting stored hours.
- Subscribe to practice changes in the shared AppLayout so Calendar and Dashboard refresh the same query families on every authenticated page.
- Initialize only new profile languages from validated signup metadata; preserve existing profile preferences and keep manual pre-login selection explicit.
- Checkout and discount preview share promoCode normalization; reject invalid supplied codes before creating a transaction so a displayed code is never silently omitted.
- Meeting duration drafts use shared minute validation and end-time arithmetic; save the meeting's chosen duration, not its service default, and only propagate explicitly changed durations across a recurring series to preserve overrides.
- Excel client imports use an idempotent atomic owner-scoped RPC; opening credits use orphan client credits and opening debts use a separate income-linked ledger, so imports never fabricate meetings or current revenue and debt payments never inflate prepaid balances.
- Invoice creation is atomic with confirmed incoming payments, deduplicated by income ID; preserve the existing numbering function and snapshot payment details, and exclude internal prepaid withdrawals to avoid duplicate invoices.
- Referral rewards live in an append-only ledger computed by DB functions (commissions from the Paddle webhook, refund reversals, own-subscription credits, payout reservations); never store an editable balance, so totals stay auditable and idempotent per payment.
- Admin payout changes use server-validated RPCs with expected-status checks, row locking and audit events; Paid requires an external transfer reference and final states cannot be edited, preventing duplicate payout bookkeeping.
- Recipient bank details are stored separately with admin-only reads and version-checked RPC writes; keep account numbers out of audit events to avoid exposing sensitive transfer information.
- Referral program settings allow direct access only through admin-scoped RLS; participants receive terms through the authenticated referral dashboard RPC so configuration is not anonymously exposed.
- Resolve new-account access through the owner-scoped versioned practice-access RPC; keep app trials separate from Paddle subscriptions and enforce restricted writes with database triggers, preserving legacy access.
- Keep public offer copy and pricing in the landing-offer module and isolated public pages; use actual product screenshots with private details excluded.
- Public product demo uses only synthetic sessionStorage state with expiry; shared presentation components accept data/callbacks and never import authenticated data hooks, preventing production reads, writes and integrations.
- Plan feature composition lives only in src/lib/planFeatures.ts (PRO = SOLO + Pro features, period-agnostic); grandfathered access uses explicit expiring legacy_plan_grants read by practice_access_state, never registration date, so plan relabels cannot drop granted access.
- Paddle webhooks are logged durably in paddle_webhook_events (unique event_id) and subscription events are applied only if newer than the last applied one per subscription, so duplicates and late retries cannot roll back status; failures return 500 so Paddle retries.
- License request approvals go only through the admin_review_license_request RPC (admin check, expected-status lock, final states immutable) and grant access via legacy_plan_grants with an expiry, never via Paddle.
- Therapist "About me" profiles keep an owner-only draft and a separate published copy plus an allow-list of published file paths; visitors read only via the booking-token RPC and storage policy on that list, so drafts and unpublished files never leak.
- "About me" visibility is gated server-side by therapist_profile_allowed (global trial cutoff, then Pro via practice_access_state) and mirrored client-side by aboutProfileAccess, so the public RPC and file policy enforce it even if the UI is bypassed.
- Public therapist profile URLs (/therapist/:slug) use a permanent unique slug reserved once by ensure_my_therapist_profile_slug on first publish; the public slug RPC returns only published, allowed content plus the existing booking key, so no second booking system exists.
- Legal document revisions use document-specific dates when only one document changes, so unchanged policies are not falsely presented as revised.
- Landing translations use explicit language-prefix URLs with a fixed English root fallback; other marketing and legal pages retain query-language URLs, so existing links remain valid.
- Generate only seven static landing HTML files from the existing shared React landing at build time; keep private/session-bound reads in browser effects and the SPA fallback intact, so crawlers see localized content without a framework migration.
- Compile build-time landing JSX with the production-compatible automatic runtime regardless of Vite mode, because publishing may combine development mode with NODE_ENV=production.
- Reuse the approved Terms operator line and provider disclosures when composing other legal documents; preserve refund-right sections and keep missing jurisdiction input in the roadmap, not public placeholders.
- Mark static fallback metadata as Helmet-managed so per-route tags replace rather than duplicate it.
- Booking confirmation email allows server-verified request owners to approve/retry without an age limit; anonymous triggers retain a ten-minute window, stored recipients and idempotency to prevent public email abuse.
- Preserve only allow-listed UTM campaign labels in sessionStorage after analytics consent and clear them on withdrawal, so registration attribution survives navigation without retaining private URL parameters.
- Landing specialist previews read only the public slug RPC and published-file storage policy, so marketing never exposes drafts or invents a specialist biography.
- Payments Unpaid rows and totals use the same expected-payment ledger, including participant-level group debts, so group parent appointments never inflate unpaid counts.

- Booking inbox page and calendar panel use the shared app translation dictionaries and active language for wall-clock formatting, so every supported language covers the same controls without per-screen fallbacks.
- Testimonial translations are keyed by the approved review ID and exact original text; render them only for fetched approved reviews and fall back to the original after edits, preventing stale or fabricated endorsements.
- Shared booking links use the active interface language in a validated lang query parameter, and Copy/Preview use the same URL; legacy links without that parameter retain visitor language detection.
- Localize landing calendar client names only in language-specific screenshot asset pointers, never in client records, so presentation changes cannot alter practice data.
- Share-preview signs photos only as an anonymous visitor under the published-file storage policy, so forged profile paths cannot bypass file ownership or publication.
- Confirmation tokens lock the appointment before the confirmation row and accept only scheduled/confirmed meetings; lookup uses the same status gate so cancellation revokes old links immediately.
- Landing share images are versioned 1200×630 browser captures of the shared localized hero with fonts loaded; language-path static HTML supplies their initial metadata without JavaScript.
- Signup email has its own six-language light presentation and optional HTTPS guide; the other account emails share a compact light shell, preserving per-event content, secure links/codes and SDK verification/delivery.
- Auth previews render synchronously to avoid the legacy React Email stream decoder corrupting multibyte Unicode; email icons are immutable HTTPS PNGs rather than font-dependent symbols.
- Group applications live in group_registrations (owner-only RLS); visitors read/submit only via token RPCs for published active groups, and confirm/transfer go through owner-checked RPCs that never delete prior applications, so history and privacy are preserved.
- Group deletion is logical (lifecycle_status/deleted_at); meetings, attendance, payments and applications are never removed by deleting a group.
